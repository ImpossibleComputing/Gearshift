# Evidence and scope notes

## Existing Gearshift evidence

These are observations from the supplied `FOLLOWUP_RESULTS.md` and the preceding source-and-record audit, not new experimental runs performed while preparing this packet:

- One frozen-model pair, Qwen3-1.7B -> Qwen3-0.6B.
- New-turn C/M/H numeric accuracy 76/78/81 on 100 questions; M-C paired interval -5 to +9 percentage points.
- The selected mapper alone received the full task/scaffold matrix. Initial affine and plaintext-functional task results under the winning scaffold are missing.
- M with the new turn stopped on EOS on all 100 items and averaged about 3.35 generated answer tokens; C averaged about 14.18.
- Full handoff-and-answer means C 450.1 ms, M 134.5 ms, H 167.2 ms; source-inclusive estimates 26.015/25.699/25.732 seconds. The large-only baseline was 25.792 seconds but used a different scaffold.
- Training arms each stopped at 128 steps, and both selected checkpoints were at the boundary. No plateau was established.
- The successful follow-up did not test long-form generation, new task families, a fresh small-only baseline, or the improved recipe on the 4B source.

The existing source-and-record audit was not an independent rerun of model inference or MPS timing. This phase-2 packet contains an experimental design, not new model results.

## Design deductions, not observed outcomes

Longer useful answers could increase the value of cheaper receiver decoding, but could also expose fidelity loss and receiver-capacity limitations. A protocol reset may improve behavioral control without being sufficient to preserve all task content. A compact textual message may outperform mapped history economically. None of those outcomes should be presumed.

The central comparisons answer different questions: C versus M tests the handoff against native receiver replay; M versus B tests the value of switching away from the source; M versus S tests whether the source work helps; M versus T/P tests whether cache translation beats simpler textual alternatives.

## Verified methodological references

These primary-source pages were checked for the evaluation design. They do not validate Gearshift's results or establish novelty.

1. Liu et al., *Is Your Code Generated by ChatGPT Really Correct? Rigorous Evaluation of Large Language Models for Code Generation* (EvalPlus / HumanEval+).
   https://arxiv.org/abs/2305.01210
   Relevant point: stronger executable tests reveal incorrect code missed by limited original tests. Use independent tests, not a judge's impression of code.
2. Zhou et al., *Instruction-Following Evaluation for Large Language Models* (IFEval).
   https://arxiv.org/abs/2311.07911
   Relevant point: some natural-language instructions can be checked programmatically. Custom tasks borrowing that approach are not official IFEval scores.
3. Min et al., *FActScore: Fine-grained Atomic Evaluation of Factual Precision in Long Form Text Generation*.
   https://arxiv.org/abs/2305.14251
   Relevant point: decompose factual prose into claims checked against reliable evidence. Phase 2 additionally proposes required-fact coverage; this custom packet metric is not an unchanged FActScore implementation.
4. Zheng et al., *Judging LLM-as-a-Judge with MT-Bench and Chatbot Arena*.
   https://arxiv.org/abs/2306.05685
   Relevant point: model judging can be useful but has position, verbosity, self-enhancement, and reasoning limitations. Blindness, order swaps, multiple judges, and human calibration mitigate some issues, not all.

Before making a novelty claim, conduct a separate primary-literature check of cache-transfer methods. Earlier discussion of related work is not an implemented paper-faithful baseline or proof of novelty.
